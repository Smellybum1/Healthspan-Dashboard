# Data model

Canonical Zod schemas live in `packages/core/src/schemas.ts` and taxonomies in `packages/core/src/taxonomies.ts`.

SQLite/Drizzle tables live in `packages/db/src/schema.ts`, `packages/db/src/intelligence-schema.ts`, and `packages/db/src/intervention-schema.ts` with migrations under `packages/db/migrations/` (`0000_init_m2` through `0005_m4_safety_portfolio`).

## Origin and mode

- `dataOrigin: "demo" | "live"` — record provenance (canonical)
- `dataMode: "demo" | "live"` — API/UI selection (default live)

Never mix origins in one response or screen.

## Core entities (domain)

- Source, SourceRecord
- ContentItem
- Paper, Trial, Intervention, Peptide
- Creator, Claim
- EvidenceAssessment
- RegulatoryEvent, Organisation
- Watchlist, ChangeEvent, ReviewTask
- SignalRadarPoint, DashboardPayload, SeedBundle, LiveBriefItem

## Live persistence tables (M2)

Operational: `sources`, `source_feeds`, `connector_checkpoints`, `ingestion_runs`, `ingestion_run_errors`, `raw_snapshots`, `background_jobs`, `scheduler_state`, …

Content: `content_items`, `external_identifiers`, `papers`, `trials` (+ child tables), `regulatory_events`, `change_events`, `app_meta`

## Live intelligence tables (M3)

- `intelligence_runs` — analysis job summaries
- `intelligence_analyses` — immutable deterministic (or AI-assisted) profiles; superseded via `superseded_at`
- `analysis_source_dependencies` — analysis ↔ source-record-version provenance
- `content_intelligence_state` — current analysis pointer + `stale` flag
- `live_claims` + `claim_source_spans` — atomic claims with required primary spans
- `claim_relationships` — potential relationships (`potentially_conflicts` never definitive contradiction)
- `live_review_tasks` + `review_decisions` — open tasks and append-only human decisions

No composite scientific longevity/truth score is persisted for Live intelligence.

Timestamps are UTC Unix milliseconds in integer columns; APIs return ISO 8601.

## Intervention / regulatory / safety tables (M4)

Identity: `intervention_entities`, `intervention_aliases`, `intervention_identifiers`, `intervention_variants`, `intervention_mentions`, `intervention_mapping_candidates`, `intervention_mention_mappings`, `entity_resolution_tasks`, `entity_resolution_decisions`

Peptides: `peptide_profiles`, `peptide_sequences`, `peptide_modifications` (source-supplied only; never invented from marketing names)

Regulatory: `regulated_products`, `regulatory_assertions` (jurisdiction/authority/product scoped — never bare “approved”)

Dossiers: `dossier_snapshots`, `dossier_source_dependencies`, `intervention_dossier_state`, `dossier_change_events`

Safety: `regulator_signal_records`, `adverse_event_query_definitions`, `adverse_event_reporting_snapshots`, `adverse_event_term_counts` (aggregates only; no patient narratives)

Trial portfolio: `trial_intervention_entity_links` (preserves source terms; registry ≠ authorisation)

Coverage vocabulary includes `not_checked`, `no_exact_match_found`, `source_unavailable`, `disabled`, `identity_unresolved`. ARTG/Drugs@FDA misses are not `unapproved`.

See ADR-0009.

## Creator / platform tables (M5)

Identity: `creator_entities`, `creator_aliases`, `creator_roles`, `creator_platform_accounts`, `creator_account_identity_candidates`, `creator_identity_tasks`, `creator_profile_statements`, `creator_profile_snapshots`, `creator_profile_state`

Monitoring & platform: `monitored_creator_sources`, `creator_content_items` (metadata-only), `platform_content_current`, `platform_content_tombstones`, `platform_compliance_events`, `platform_retention_job_results`, `platform_policy_state`, `platform_policy_versions`, `platform_quota_ledgers`, `platform_price_tables`, `x_budget_ledger`

Documents: `creator_documents` (user-supplied / authorised transcripts with rights basis), `creator_document_segments`

Claims & alignment: `creator_claims`, `creator_claim_source_spans`, `creator_claim_concepts`, `creator_claim_links` (legacy bridge), `creator_claim_evidence_links`, `creator_claim_alignment_assessments`, `creator_claim_alignment_dimensions`, `creator_claim_findings`, `creator_claim_relationships`, `creator_corrections`, `creator_disclosures`, `creator_events`, `claim_recurrence_snapshots`

Schema depth migration: `0007_m5_creator_schema_depth` (ALTER existing M5 tables + CREATE §14 entities). Business logic for connectors/alignment ships in later M5 packets.

YouTube API metadata is never claim evidence. X is optional, budget-capped, and never sent to external AI. No creator trust/credibility/misinformation/influence/attention/engagement/popularity scores.

See ADR-0010.

## Seed data (Demo)

Generated by `scripts/generate-seed.mjs` into `packages/core/src/seed/bundle.ts`.

- All seed records use `dataOrigin: "demo"`
- UI shows a persistent demo snapshot notice in Demo mode
